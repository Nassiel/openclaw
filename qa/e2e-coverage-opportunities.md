# E2E QA Lab coverage opportunity ledger

coverage. It is intentionally risk- and behavior-oriented: a row is not selected
only because a taxonomy ID is empty or a test count can increase.

Statuses: `backlog`, `selected`, `in progress`, `blocked`, `review-ready`,
`merged`, or `rejected`.

## Rejected during this scan

- Additional TUI scenarios: every current `tui.*` taxonomy boundary already has
  a primary PTY owner; another scenario would duplicate stronger coverage.
- Registering arbitrary mocked Control UI tests as new QA coverage: accounting
  alone does not materially reduce product risk without a real-Gateway boundary.
- Shallow cron restart duplication: `cron-state-contracts` already covers the
  service-level store/timer lifecycle. E2E-016 was selected only because it adds
  the distinct real-Gateway startup projection and `cron.list` outcome.
